# OOMU 로컬 개선 및 검증 기록

작성일: 2026-11-02. 이 기록은 앱 전체의 출시 완료 선언이 아니다.

## 적용한 변경

- 가입 완료 판단을 명시적인 `isProfileComplete`로 통일했다. 기본 닉네임·동네만으로 신규 가입 설정을 건너뛰지 않는다. 기존에 명시적으로 완료된 프로필과 기존 관리자 분기는 유지했다.
- 일반 신규 회원에게 나이·성별·동네·직업·성향·타인 사진을 임의로 채우지 않는다.
- 프로필 설정의 미리 채운 개인정보·인증번호·인증 완료 상태와 가짜 닉네임 중복 확인을 제거했다.
- 휴대폰 번호는 로그인한 계정에 Firebase 자격 증명으로 연결한다. 다른 계정에 연결된 번호를 자동 병합하지 않는다. 프로필 저장 시 실제 Auth 번호와 입력 번호가 일치해야 한다. SMS 수신은 신원/PASS 인증으로 표현하지 않는다.
- 카카오 화면의 임의 간편 계정 경로를 제거하고 기존 공식 OAuth 진입으로 연결했다. Google 취소·실패와 이메일 입력 오류는 사용자용 문구로 표시한다. 비밀번호 보기, 원문 비밀번호 보존, 컨트롤러 해제 및 작은 화면 스크롤을 적용했다.
- 모임 상세의 3초 자동 승인 및 즉시 채팅 합류 시뮬레이션을 제거했다.
- 실제 신청 저장·대기 상태·모임장 승인/거절을 위한 트랜잭션과 화면을 추가했다. 서버 검증 전 노출되지 않도록 `OOMU_ENABLE_APPLICATIONS`는 기본 false다.
- 새 모임에 `hostUid`, `participantIds`를 저장하고, 장소/이벤트에서 개설한 모임에 `sourceEventId`, `sourceEventTitle`을 보존한다.
- 블럭/목록 카드가 공통 호스트·온도·인원 영역을 사용한다. 좁은 화면이나 글자 확대에서는 세로로 나눈다. 일반 목록의 번개 장식을 줄였다.
- 상세 호스트 이름과 온도계를 분리했다. 임의의 참여자 사진, 무관한 기본 소개문, 가짜 기본 정원·일정 표시를 제거했다.
- 주소와 길찾기를 별도 행으로 배치하고 하단 고정 버튼을 본문 레이아웃 밖으로 분리했다. 과한 남색 스크롤 상단바와 하단 보정 공백을 정리했다.
- 장소 검색 실패 시 역/동네 좌표를 실제 장소 좌표로 대체하지 않는다. 검색 결과의 일부 일반 단어만 일치하는 경우도 확정하지 않는다. 기존 DB의 저장 좌표 정확성까지 보증하는 것은 아니다.
- 이벤트 제목을 사진 밖으로 옮기고 길찾기를 보조 액션으로 정리했다. 근거 없는 KOPIS 소개·무드·상시 운영 기본값을 제거했다. 제목 원문을 바꾸지 않고 표시 폭을 측정하는 컴포넌트를 추가했다.
- 이벤트 상세에서 연결된 모임을 조회하고, 없으면 모임 개설로 이어지도록 구성했다. 복사 알림만 뜨던 공유 동작은 실제 장소 정보 복사로 바꿨다.
- 댓글과 댓글 수는 함께 저장한다. 저장 전 성공 표시/입력 삭제/로컬 댓글 추가를 하지 않는다. 실패하면 입력이 남는다.
- 운영 홈 진입의 데모 DB 생성은 기본 비활성이다. 릴리스 빌드에서 빈 모임 목록을 가짜 모임으로 채우지 않는다.
- 누락되어 있던 웹 진입 HTML을 추가하고 IDE의 Flutter SDK 경로를 실제 설치 위치로 정정했다.

## 출시 전 남은 확인

1. 신청 기능은 비활성 상태다. 서버 규칙에서 신청자 본인·모임장 권한과 정원/상태 변경을 검증하고, 테스트 환경에서 실제 신청·승인·거절·동시 승인·권한 거부를 확인한 후에만 활성화해야 한다. 클라이언트 검사만으로 권한을 보장하지 않는다.
2. 기존 모임 중 `hostUid`가 없는 데이터는 모임장 신원을 추측해서 채우지 않는다. 별도 데이터 확인이 필요하다. 기존 운영 문서는 변경하지 않았다.
3. 기존 중복 계정의 병합이나 Google/카카오 전체 로그인 수단 연결 관리까지 완성한 것은 아니다. 현재는 휴대폰 번호의 중복 연결을 거부하고 기존 로그인으로 안내한다.
4. 실제 SMS, Google·카카오 외부 인증 복귀, 계정 연결 충돌은 운영 계정으로 실행하지 않았다. 클라이언트 구현·컴파일과 실제 외부 연동을 구분해야 한다.
5. Android 실기기/에뮬레이터는 실행하지 않았다. 웹 캡처와 위젯 테스트를 네이티브 검증으로 대체 보고하지 않는다.
6. 이벤트/핫플 원본의 정확성·최신성, 기존 저장 좌표, 운영의 과거 더미 댓글·문구는 별도 확인 대상이다. 코드 수정으로 기존 DB 내용을 지웠다고 보고하지 않는다.
7. 채팅 참여 권한·퇴장/재입장·알림 전달, 모임 일정/정원 개설 흐름의 실제 저장과 조회는 후속 통합 검증 대상이다. 이번 변경을 앱 전체 E2E 통과로 표현하지 않는다.

## Git/배포

사용자 승인 전에는 git add/commit/push를 실행하지 않는다. 현재 저장소는 main 푸시 시 GitHub Actions로 웹 자동 배포가 실행되므로, 업로드 확인에는 이 영향도 포함해 안내한다. 보호된 보안 지침 파일과 운영 DB는 변경하지 않았다.

## 11월 3일 추가 검수: 채팅과 페이지 이동

- 운영 채팅의 자동 예시 메시지·카드 생성, 자동 AI 호출, 가짜 일정·정산·안전귀가·매칭 대화를 제거했다. 기존 Firestore 데이터는 삭제하지 않았으며, 과거 데모 문서는 확인된 식별자와 내용이 일치할 때 화면에서 제외한다.
- 채팅 목록과 채팅방은 현재 UID가 참여자로 확인된 방만 보여준다. 발신자 구분은 닉네임이 아닌 UID 기준이다. 메시지 전송은 저장 성공 후 표시하며, 실패 시 입력 내용을 유지한다. 읽기 오류와 빈 상태를 구분한다.
- 사진·위치·일정·투표·안전귀가 등은 사용자가 메뉴에서 직접 선택하는 동작으로만 제공한다. AI 대화 주제도 버튼을 누를 때만 요청하고, 선택한 질문은 입력창에 초안으로 놓는다.
- 커뮤니티 게시글 작성은 실제 저장 성공 후에만 완료 처리한다. 알림 화면의 고정 예시 5건을 제거했다. 홈의 커뮤니티 목록은 Firebase 사용 시 실제 게시글만 보여주며, 오류와 빈 상태를 구분한다.
- 홈의 5개 탭, 채팅 복귀, 커뮤니티 상세 이동을 로컬 위젯 테스트로 확인했다. 커뮤니티 상세 제목의 한글 어절 줄바꿈을 보완했다.
- 현재 검증: `flutter test` 59/59 통과(종료 0), 웹 프리뷰/릴리스 빌드 종료 0, 보안 규칙 검사 종료 0, `git diff --check` 종료 0. `flutter analyze`는 오류 0·경고 19·정보 330으로 종료 1이며 전체 통과가 아니다.
- 로컬 웹 고정 예시 캡처에서 빈 채팅방, 사용자가 작성한 메시지만 있는 채팅방, 수동 추가 메뉴, 커뮤니티 상세를 확인했다. 실제 Firebase 계정·운영 데이터·Android 단말에서의 통합 동작은 미검증이다.
- 새 모임과 채팅방은 일괄 저장으로 맞췄다. 저장 실패를 무시하고 개설 성공을 띄우지 않는다. 승인 기능이 활성화되면 모임 승인과 채팅방 `participants` 추가를 같은 트랜잭션에서 처리하도록 연결했다. 다만 이 경로는 기본 비활성이고 서버 권한·실제 계정으로 검증되지 않았다.
- 소개팅 탭의 고정 예시 팟과 존재하지 않는 채팅방으로 보내던 버튼을 제거했다. 실제 Firestore 모임 중 소개팅·미팅 분류만 표시하고 없으면 빈 상태를 보여준다. 390px 로컬 웹 캡처로 확인했다.

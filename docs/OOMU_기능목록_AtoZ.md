## 읽는 법

기능마다 "그 기능 안에서 일어나는 일"을 처음부터 끝까지 적었다. 한 줄씩 실측해서 4칸(화면·데이터·백엔드·디자인)을 채우고, **전부 통과하면 그 기능을 고정**한다.
모든 기능에 공통으로 들어가는 디자인 항목(AI티 없음, 글 겹침·잘림 없음, 여백 토큰, 360/390/430px·글자 크게, 터치 48px, 빈 상태·로딩·오류 화면)은 매번 적지 않았다. 각 기능 검사 때 반드시 함께 본다.

"현재"는 2026-11-27에 확인한 사실만 적었다. 확인하지 않은 것은 비워 두었다.

## A. 시작·계정 (11개)

### A1. 앱 첫 실행·자동 로그인(세션 유지)
- 첫 실행 → 로그인 화면, 로그인한 적 있으면 바로 홈
- 새로고침·앱 재시작 후에도 로그인 유지, 다른 계정 정보가 섞이지 않음
- 서비스 워커 캐시 때문에 예전 화면이 남지 않음
- 네트워크 끊김 시 안내(토스트), 다시 연결되면 정상

### A2. 이메일 회원가입
- 회원가입 → 이메일·비밀번호 입력(형식 오류 안내, 비밀번호 보기 버튼) → 가입 → 프로필 설정(A8)으로 이동
- 이미 가입된 이메일이면 "이미 가입" 안내와 로그인 유도
- Firestore `users/{uid}` 생성, 전화번호·이메일은 `private/contact`에만 저장
- 현재: 테스트 계정 3개 가입·로그인 성공(2026-11-27)

### A3. 이메일 로그인·이메일 찾기·비밀번호 재설정
- 로그인 → 홈, 틀린 비밀번호·없는 계정 안내 문구
- 이메일 찾기, 비밀번호 재설정 메일 발송 → 실제 메일 수신 → 새 비밀번호로 로그인
- 현재: 로그인 성공 확인. 찾기·재설정은 미검증

### A4. 카카오 로그인 / A5. 네이버 로그인 / A6. 구글 로그인
- 버튼 → 각 회사 로그인 → 앱으로 복귀 → 신규면 프로필 설정, 기존이면 홈
- 같은 사람이 다른 방법으로 들어와도 계정 1개(중복 가입 방지)
- 서버에서 토큰 검증(카카오·네이버는 서버 Custom Token)
- 버튼 브랜드 색 정확
- 현재: 카카오·네이버는 서버(Cloud Functions)가 404라 동작하지 않을 가능성이 높다(체크리스트 4번)

### A7. 휴대폰 문자 인증
- 번호 형식 검사 → 발송 → 3분 타이머 → 재전송 대기 → 6자리 입력 → 성공·실패 안내
- 하루 요청 한도(10회), 틀린 코드·만료 안내
- 인증 기록은 서버에만(`phone_verifications`는 클라이언트 접근 차단)
- 입력칸 높이 48 이상, 글자 16px 이상(아이폰 확대 방지)
- 현재: 문자 문구는 마지막 변경(1e455d0) 그대로. 서버 404라 실제 발송 안 됨

### A8. 프로필 설정(가입 직후)
- 단계별 입력: 닉네임, 생년월일(만 19세 미만 차단), 성별, 휴대폰 인증, 동네, 대표 사진, 직업·MBTI·취미·성격·음주
- 저장 → `isProfileComplete: true` → 홈
- 중간에 나갔다 들어와도 입력값 유지 여부
- 사진은 R2 주소로 저장(Data URL 폴백 금지)
- 현재: 문자 인증이 서버 의존이라 신규 가입자는 이 단계에서 막힐 수 있다

### A9. 동네 설정·변경
- 홈 상단 동네 이름(▾) → 동네 선택·인증 → 홈·커뮤니티·지도·발견이 새 동네로 바뀜
- 긴 동네 이름이 잘리지 않음("여수시 화…" 금지)
- 다른 동네 글·모임이 섞이지 않음

### A10. 로그아웃·계정 전환
- 설정 → 로그아웃 확인(바텀시트, alert 금지) → 로그인 화면
- 다른 계정으로 로그인했을 때 이전 사람의 동네·닉네임·찜·차단 목록이 남지 않음
- 늦게 도착한 이전 계정 응답이 새 계정 화면을 덮지 않음(세션 세대 검증)

### A11. 회원 탈퇴
- 설정 → 회원 탈퇴 안내 → 확인 → 로그인 화면, 같은 계정으로 다시 로그인 불가
- `users/{uid}`·`private/contact`·`user_states` 삭제, 공개 프로필이 남지 않음
- 웹 삭제 요청 페이지(`web/delete_account.html`) 동작
- 쓴 글·채팅·R2 사진 처리 방침
- 현재: 보안 규칙이 2026-11-27 게시로 본인 users 삭제를 허용. 실측은 아직

## B. 프로필 (5개)

### B1. 사진 올리기(프로필·대표 사진)
- 사진 찍기·앨범에서 선택 → 미리보기 → 저장 → 새로고침 후에도 그대로
- R2 영구 주소로 저장(Firestore에 이미지 통째 저장 금지), 실패 시 안내 문구
- 원형 잘림 정상, 실패 시 깔끔한 대체 이미지(엑박 금지)
- 현재: 서버 서명 실패 시 Data URL로 저장하는 폴백이 있고, 서버가 404라 R2 업로드가 안 될 가능성이 높다(체크리스트 7·14번)

### B2. 프로필 수정
- MY → 프로필 수정 → 닉네임·사진·소개·취향 수정 → 저장 → MY에 즉시 반영
- 남의 프로필 수정 불가, 전화번호 등은 남에게 안 보임
- 긴 닉네임 말줄임, 태그 줄바꿈 정상

### B3. 프로필 미리보기·남이 보는 프로필
- 내 프로필이 남에게 어떻게 보이는지 미리보기
- 다른 사람 프로필(모임 호스트·참여자·글쓴이 눌러서) → 사진·닉네임·나이·성별·동네·매너온도·후기
- 빈 값은 "정보 없음"(가짜 값 금지), 차단한 사람은 열리지 않음

### B4. 프로필 전역 동기화
닉네임·사진을 바꾼 뒤 아래가 모두 바뀌는지: MY, 남이 보는 프로필, 내가 쓴 글, 내가 쓴 댓글, 채팅 말풍선, 내가 연 모임의 호스트 표시, 모임 참여자 목록
- 현재: 글·댓글·채팅·모임에 작성 당시 닉네임·사진을 복사해 저장하는 구조라 실패가 예상된다(검사기준 8번 표)

### B5. 매너온도·받은 후기
- 새 회원 36.5°C, 후기에 따라 변화, 본인이 임의로 올릴 수 없음
- MY·프로필·모임 카드의 온도가 같은 값
- 현재: 2026-11-27 규칙 게시로 본인 수정은 차단됨(에뮬레이터·운영 대조 완료)

## C. 모임 (9개)

### C1. 홈 모임 목록
- 카테고리 칩(전체·오늘 번개·이번 주말·카페·디저트…) 필터, 정렬(최신순 등), 더보기
- 내 동네 모임만, 지난·마감 모임은 아래로 또는 숨김
- 카드: 사진 비율 고정, 제목 2줄 말줄임, 호스트·매너온도·인원·모집 상태
- 빈 동네는 빈 상태 화면(문구 + 모임 열기 버튼)
- 현재: 단어 중간 줄바꿈("하/이볼"), 코랄 남용(디자인 검수 D3·D6)

### C2. 모임 생성 (예시 기준, 검사기준 5-2)
- 디자인: AI티 없음(카테고리 이모지 🍲🎭🎲⚡☕🌸 제거 필요), 글 겹침 없음, 여백 적당
- 입력: 사진(R2) · 카테고리·세부 분류·태그 · 제목 · **날짜·시간 선택 UI가 우무 디자인에 맞음** · 정원 · 비용 · 소개
- 지도: 네이버 지도 표시, 장소 검색 → 선택 → **마커 위치 정확**, 동네 기준 거리
- 저장: 바로 홈 목록에 보임, Firestore 값 = 입력값, 모임 단톡방 함께 생성
- 권한: 비로그인 개설 불가, 남의 이름으로 개설 불가
- 현재: 개설 화면 캡처 완료(이모지·2px 코랄 테두리·베이지 입력칸 확인). 저장 이후는 미검증

### C3. 모임 상세 보기
- 사진·카테고리·제목·일시·장소·인원·비용·호스트(프로필 보기)·소개·지도·참여 멤버·안전 수칙·신고·차단
- 지도: 네이버 지도·핀·"네이버 지도"·"길찾기" 버튼 동작
- 하단 고정 버튼: 내 상태에 따라 "참여 신청하기 / 신청 중 / 참여 중 / 마감 / 내 모임 관리"
- 현재: 화면 캡처 완료. 검수 환경에서 지도 이미지 주소가 막혀 지도 판정 보류

### C4. 참여 신청·승인·거절·정원 마감
- B 신청(혼자·친구 1명, 메시지) → **모임장 A에게 알림**
- A가 신청 목록 보기 → 승인 → **B에게 승인 알림**, B가 참여자·단톡방에 추가, 인원 수 = 실제 명단
- 거절 → B에게 알림, B 화면 상태 변경
- 정원 차면 "마감", 더 신청 불가
- 제3자 C는 남의 신청 승인·명단 조작 불가
- 현재: 보안 규칙 에뮬레이터 테스트로 권한은 확인(2026-11-27). 승인 알림은 앱 안 알림만 있고 **문자(SMS)는 없음**(서버 필요)

### C5. 모임 나가기·참여 취소
- 참여자 B가 나가기 → **B만** 빠짐, 다른 참여자 영향 없음, 인원 수·단톡방·서버 문서 반영
- 신청 대기 중 취소
- 현재: 신청 취소(삭제)는 보안 규칙상 관리자만 가능, 거절된 사람은 재신청 불가(대표 결정 필요)

### C6. 찜(하트)·찜한 모임
- 하트 → MY "찜한 모임"에 보임, 새로고침 유지, 1인 1회
- 하트만 코랄
- 지워진 모임이 찜 목록에 남지 않음

### C7. 오늘 번개(소소스팟)
- 홈 번개 섹션 → 번개 목록·상세 → 즉시 합류 / 번개 개설
- 현재: 화면에 장식 이모지(⚡) 다수, 하드코딩 색·글자 크기가 많은 파일(`oomu_spot_screen.dart`)

### C8. 참여한 모임(MY)
- MY "참여한 모임" 개수 = 실제 참여 수, 목록 → 모임 상세·단톡방 이동

### C9. 지도로 모임 찾기
- 홈 상단 지도 아이콘 → 지도 화면 → 동네 모임 핀 → 누르면 모임 상세
- 현재 위치 버튼(권한 거부 시 동네 기준 + 안내)
- 현재: Android 위치 권한 선언 없음(체크리스트 17번)

### D1. 글 목록·카테고리 필터

### D2. 글 쓰기·수정·삭제

- 수정·삭제는 글쓴이만, 삭제 확인은 바텀시트
- MY "내가 쓴 글" 개수·목록 반영
- 남의 이름으로 글 작성 불가(2026-11-27 규칙 게시로 차단)

### D3. 글 상세·댓글
- 댓글 작성·삭제 → 상세와 목록의 댓글 수가 같이 바뀜

- 입력창 키보드에 안 가림, 빈 댓글 안내
- 현재: 반짝이 버튼(움짤) 아이콘이 AI티(D5)

### D4. 좋아요(글·댓글)
- A가 누르면 B 화면도 +1, 연타해도 1, 취소 가능, 음수 없음, 새로고침 유지
- 현재: 규칙상 1인 1회·숫자 조작 차단 확인(에뮬레이터·운영 대조). 화면 2계정 실측은 아직

### D5. 글·댓글 신고·숨기기

## E. 채팅 (5개)

### E1. 채팅 목록
- 참여한 단톡방·1:1방, 마지막 메시지·시간·안 읽은 수, 검색
- 빈 상태(아이콘 + 한 줄 + "동네 모임 둘러보기") — 현재 정상 표시 확인
- 현재: 앱바 검색 아이콘과 검색창이 중복(D13)

### E2. 채팅방 실시간 대화
- A가 보내면 B 화면에 바로, 순서·시간 정확, 읽음·안 읽은 수 갱신
- 긴 메시지 줄바꿈, 입력창이 키보드 위, 참여자가 아니면 읽기·쓰기 불가

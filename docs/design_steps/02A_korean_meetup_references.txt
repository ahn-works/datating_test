OOMU 한국 모임 앱 레퍼런스 적용 — 기존 02단계 다음, 03단계 전에 사용
조사일: 2026-10-27

[이번에 확인한 범위]
문토·프립의 로그인 없는 공개 웹 화면을 직접 보았다. 소모임·위피의 공식 스토어 설명, 당근 SEED 공식 문서도 확인했다. 경쟁 앱을 설치하여 네이티브 내부 화면·전체 상태를 검수한 것은 아니다. 화면을 보지 못한 앱은 관찰했다고 쓰지 않는다. 아래 OOMU 수치는 경쟁 앱 실측값이 아닌 초기 제안이다.

[레퍼런스 역할]
1. 문토: 모임/소셜링/클럽/챌린지처럼 목적을 구분하는 탐색 구조, 밝은 바탕과 사진·제목으로 분위기를 만드는 방식의 참고 대상.
   관찰: 공개 웹 상단에는 큰 기획 배너와 다수의 카테고리가 있다. OOMU의 현재 정보 과밀을 고려해 배너·카테고리 개수를 그대로 가져오지 않는다.
   https://www.munto.kr/
2. 프립: 사진 → 지역 → 제목 → 후기 → 가격 순서로 역할을 구분한 공개 상품 카드의 정보 위계 참고.
   관찰: 카드 전체를 무거운 테두리로 둘러싸기보다 사진과 글자 정렬로 묶는다. 배지·할인·긴 홍보 문구도 많으므로 그것까지 따라오지 않는다. OOMU에서는 가격보다 날짜·장소·참여 인원 우선순위를 검토한다.
   https://www.frip.co.kr/
3. 소모임: 취미/지역을 통해 모임을 찾고 정모에 참여하는 과업을 참고. 스토어 설명과 공개 서비스 안내를 확인했으며, 네이티브 정모 화면의 정확한 배치나 수치를 확인한 것은 아니다.
   https://www.somoim.co.kr/helps
   https://apps.apple.com/kr/app/id582910479
4. 위피: 프로필의 관심사와 구체적인 글·사진을 대화 시작점으로 활용하는 방식 참고. OOMU의 모임 탐색 화면을 사람 평가·외모 선택 중심으로 바꾸지는 않는다.
   https://apps.apple.com/kr/app/id1261209014
5. 당근 SEED: 간격, 타이포그래피, 색의 역할, 버튼과 상태의 일관성을 정할 때 가장 먼저 참고할 공식 문서.
   https://seed-design.io/foundations/spacing
   https://seed-design.io/foundations/typography
   https://seed-design.io/components
   https://seed-design.io/ai-integration
   https://github.com/daangn/seed-design
   공식 간격 문서에는 화면 좌우 기본 16px, 칩 사이 8px 등 역할별 토큰이 제시되어 있다. 글자도 크기뿐 아니라 줄 높이와 두께를 함께 정의한다. SEED의 현재 웹 구현·Doctor를 Flutter용 패키지나 일반 시각 검수 도구로 취급하지 않는다. 문서의 원리를 Flutter ThemeData/TextTheme/위젯으로 구현한다.

[목표 분위기 — 디자인 가설]
2030 여성이 안전하고 편안하게 모임을 탐색하고 직접 열 수 있는, 밝고 차분한 생활 커뮤니티.
밝은 중립 배경 + 선명한 글자 + 절제된 로즈 강조색 + 일상적인 활동 사진.
성별만으로 분홍색·둥근 장식·귀여운 일러스트 선호를 단정하지 않는다. 실제 대상 사용자 반응으로 확인할 가설이다.
기존 03단계 팔레트와 공통 토큰을 우선하며 새로운 경쟁사 색을 추가하지 않는다.

================ 안티그래비티에 아래부터 붙여 넣기 ================

OOMU 프로젝트의 한국 모임 앱 레퍼런스를 실제 화면 설계에 연결해줘.
프로젝트: C:\Users\DT4\Downloads\oomu_app
보안 문서·보안 코드는 이번 작업에서 읽거나 수정하지 마.
진행 중인 기존 작업을 저장한 뒤 실행하고, 검증된 원본 백업과 docs/UI_PROGRESS.md를 먼저 확인해줘. 백업이 없으면 기존 01단계를 먼저 완료해줘.

이번 작업은 디자인 방향 확정 단계다. 앱 전체 코드 수정, 기능 추가, 패키지 설치, DB 쓰기, git 및 배포는 하지 마.

1. docs/OOMU_UI_GUIDE.md와 현재 실제 진입 화면만 확인해줘. 이 파일 위쪽의 출처 링크와 관찰 범위를 참고해줘. 공식 문서나 공개 화면을 실제로 읽지 못하면 미확인이라고 쓰고, 앱 이름만 보고 디자인을 추측하지 마.

2. 문토·프립·당근을 각각 목적이 있는 참고 대상으로 사용해줘.
   - 문토: 모임을 고르는 분위기와 탐색 목적의 구분.
   - 프립: 카드 안에서 사진·제목·보조 정보의 위계.
   - 당근 SEED: 글자·간격·컨트롤·상태의 일관성.
   - 소모임·위피는 확인 가능한 과업과 프로필 정보 구성만 보조 참고.
   여러 앱의 색·버튼·카드를 섞어 붙이지 말고 OOMU의 기존 한 가지 디자인 기준으로 재해석해줘. 브랜드 로고·사진·문구·일러스트를 OOMU 자산으로 가져오지 마.

3. 확인된 백업과 별개로 격리된 로컬 미리보기에서, 같은 모임 데이터로 홈과 상세 화면의 정적인 디자인 시안을 만들어줘. Flutter 미리보기를 우선하고, 실행 환경이 없으면 격리된 HTML 시안을 사용할 수 있지만 실제 Flutter 구현·검증과 구분해줘. 한 방향의 전후 화면을 나란히 비교할 수 있게 해줘. 배포·DB 연결 없이 시안임을 명시하고 실제 사용자 데이터나 참가 수를 만들어 운영 화면에 저장하지 마.

4. 시안의 필수 기준:
   - 홈: 동네/검색/필터 다음에 모임을 쉽게 찾게 구성. 광고·LIVE·이벤트가 동시에 주목을 요구하지 않게 해줘.
   - 카드: 제목, 날짜·시간, 동네, 현재 인원/정원 순서의 가독성을 우선 검토. 2열을 강제하지 말고 긴 한글과 정보량에 맞게 선택해줘.
   - 상세: 사진의 분위기는 살리고 날짜·장소·인원·호스트·소개·참여 행동의 순서를 명확히 해줘. 보조 지도 버튼은 주 참여 버튼보다 조용하게 해줘.
   - 기존 로즈 강조색은 주요 행동과 선택 상태에 제한해서 사용해줘. 검증되지 않은 인증·안전 문구를 꾸며 넣지 마.
   - 좌우 여백 16~20, 카드 내부 16, 관련 정보 사이 6~8, 묶음 사이 12~16, 섹션 사이 24~32 논리 픽셀을 출발점으로 삼되 광학적 균형에 맞게 조정해줘. 이는 OOMU 제안이며 경쟁 앱 실측값이라고 쓰지 마.
   - 제목/본문/보조 글자의 역할별 크기·두께·줄 높이를 같이 정해줘. 한글 자간을 일괄로 넓히거나 줄이지 말고, 말줄임으로 겹침을 숨기지 마.
   - 아이콘의 보이는 크기와 터치 영역을 분리해줘. 보조 아이콘은 작고 정돈되게, 터치는 충분하게 유지해줘.

5. 390 너비에서 현재 화면과 시안을 비교하고, 360/430 및 큰 글자에서 정보 잘림과 버튼 겹침을 확인해줘. 스크린샷 출처·웹/앱 구분·관찰 사실·OOMU 제안을 분리해줘. 실제 네이티브 화면을 안 봤다면 봤다고 보고하지 마.

6. 비교 자료와 선택한 기준만 docs/OOMU_UI_GUIDE.md 및 docs/UI_PROGRESS.md에 짧게 반영해줘. 상시 지침이나 스킬 파일을 더 늘리지 마. 결과를 보여주고 이 단계에서 멈춰줘. 실제 앱 코드는 기존 03단계에서 상세 화면 하나부터 적용한다.

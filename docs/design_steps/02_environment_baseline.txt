OOMU의 docs/OOMU_UI_GUIDE.md와 docs/UI_PROGRESS.md를 읽고 2단계만 진행해줘. 보안 전용 파일은 읽거나 수정하지 마.

이번 목표는 '현재 로컬 코드의 실행 결과를 실제로 볼 수 있는 환경'을 만드는 것이다. 디자인 변경은 아직 하지 마.

1. 직전 단계의 ZIP 백업 검증 결과와 실제 프로젝트 경로를 확인해줘.
2. Flutter/Dart SDK, pubspec.lock, IDE의 Flutter SDK 경로, 의존성 상태를 확인해줘. C:\flutter 같은 경로는 실제 존재 여부를 확인하고 사용해줘.
3. 기존 정상 SDK가 있으면 우선 사용해줘. 없다면 공식 Flutter 배포에서 프로젝트와 호환되는 SDK를 프로젝트 외부의 C:\Users\DT4\Downloads\oomu_dev_tools 아래에 설치하는 것은 허용한다. 프로젝트의 IDE SDK 경로만 필요한 만큼 설정하고, 시스템 전역 PATH·관리자 설정·의존성 일괄 업그레이드는 하지 마. 도구의 권한 요청이 필요하면 우회하지 마.
4. flutter analyze와 기존 flutter test를 실행해 수정 전 결과를 기록해줘. 실패를 지우거나 검사 예외를 추가해 통과시키지 마.
5. 현재 소스로 로컬 Flutter 웹을 실행하고 주소와 사용한 진입점을 기록해줘. 운영 데이터를 생성·수정하는 조작 없이 현재 계정·기존 테스트 상태에서 볼 수 있는 화면만 확인해줘. 새로운 데이터 쓰기가 필요하면 별도 승인 전에는 수행하지 마.
6. 실제 홈·모임 상세·프로필·커뮤니티의 수정 전 스크린샷을 가능한 범위에서 저장해줘. 뷰포트는 390×844 logical pixel 기준을 기록해줘.
7. 공개 주소 https://ahn-works.github.io/datating_test/ 는 기존 배포 참고용으로만 구분해줘. 로컬 변경을 배포하지 않았는데 공개 화면을 변경 후 결과라고 보고하지 마.
8. 안드로이드 실행 환경도 있으면 기기 목록을 확인해줘. 없으면 웹 확인과 안드로이드 확인을 구분해 남기고, 이번 단계에서 대규모 안드로이드 개발 도구 설치까지 확장하지 마.

실행 환경이 막히면 필요한 조건을 구체적으로 보고하고, 이후 대규모 UI 변경은 시작하지 마. 실행 URL·SDK 버전·실제 실행한 검사·기준 스크린샷·남은 장애만 기록하고 여기서 끝내줘. 앱 기능·DB·인증·보안·git·배포는 변경하지 마.

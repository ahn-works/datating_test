OOMU 디자인 정리: 확인한 문제와 단계별 실행 순서
2026-10-27 / 원본 프로젝트는 수정하지 않음

범위: 디자인과 에이전트의 UI 작업 지침. 보안은 분석·수정 대상에서 제외.
이 파일들은 실행 요청문이며 앱 백업이나 새 상시 규칙 묶음이 아니다.
프로젝트의 rules/skills 폴더에 통째로 넣지 말고, 해당 단계 하나만 채팅에 붙여 넣는다.
근거: 앞서 직접 확인한 390×844 웹 화면, 현재 UI 코드와 디자인 지침.
지침이 실제 모델 성능을 얼마나 떨어뜨렸는지는 측정하지 않았다.
다만 중복·충돌·오래된 경로가 있다는 것은 파일에서 확인했다.

[지침에서 확인한 문제]
1. AGENTS.md, AI_INSTRUCTIONS.md, 통합 규칙, 디자인 규칙, frontend-design 스킬에 같은 벤치마킹·완성도 문구가 반복된다.
2. 최우선·절대·100점·12년 차 같은 수식어에 비해 화면별 완료 기준은 부족하다.
3. 분홍 코랄 #F25767, 주황 코랄 #FF5E36, #FF6B4A 계열이 서로 다른 기준으로 사용된다.
4. 사용자는 2030 여성 중심의 안전하고 자유로운 모임을 목표로 하지만 일부 지침은 30대 싱글·설렘·소개팅·B2B 홍보를 한꺼번에 앞세운다.
5. 라우팅 지침의 lib/features/home, party, venue, admin, chat 화면 경로 중 확인한 5개가 현재 존재하지 않는다.
6. 모든 Row에 한 줄 말줄임, 모든 피드에 대칭 2열 같은 규칙은 제목·주소·설명의 역할 차이를 반영하지 못한다.
7. wordBreak: WordBreak.keepAll을 Flutter 기본 Text에 전역 적용하라는 지침은 현재 공식 Text API와 맞지 않는다.
8. 매번 여러 서비스 전체를 벤치마킹하고 모든 문서를 읽도록 요구해, 이미 결정된 디자인을 유지하는 기준이 약하다.
9. UI 마무리 조건에 git push와 배포가 섞여 있다. 로컬 수정·검수·배포를 분리해야 한다.
10. 문서에 '자동 로드'라고 적힌 것만으로 실제 IDE에서 활성화된 규칙이라고 확인할 수 없다.

[실제 화면·UI 코드에서 확인한 문제와 개선 판단]
11. 공통 TextTheme와 Pretendard 등록이 없고 개별 글자 스타일이 많아 화면별 크기·굵기·행간이 달라진다.
12. 작은 글자에 굵은 폰트를 많이 사용하고 제목·본문·보조정보의 무게 차이가 부족하다.
13. 홈 상단에 카테고리·지도 배너·접속 문구·LIVE·트렌드·칩·도트가 모여 핵심 모임 탐색이 늦게 보인다.
14. 칩·보더·그림자·이모지·색상 강조가 누적되어 각 요소가 서로 주목을 요구한다.
15. 모임 상세의 큰 커버와 호스트 카드가 일정·장소보다 먼저 넓은 공간을 차지한다.
16. 상세 호스트 카드에서 인증 문구와 온도 막대가 실제로 겹쳤다.
17. 390px에서 동네명·섹션명·주소가 빨리 잘린다. 필요한 정보까지 한 줄로 제한하는 규칙을 재검토해야 한다.
18. 카카오맵의 아이콘 자체는 확인한 곳에서 16~18 크기도 사용한다. 아이콘 크기뿐 아니라 버튼의 노란 면적·패딩·위치를 조정해야 한다.
19. 외부 지도·길찾기 같은 보조 행동이 참여 신청 같은 주요 행동과 시각적으로 경쟁한다.
20. 프로필에서는 아바타·대표사진이 반복되고 멤버십 배너의 비중이 크다. 프로필 확인·수정 목적에 맞는 우선순위 정리가 필요하다.
21. 'LIVE', 접속자·인증·참여 관련 표현은 확인 가능한 상태와 연결해야 한다. UI를 풍성하게 보이게 하려고 수치·인증 문구를 추가하지 않는다.
22. 안심귀가·매칭은 이후 기능 과제다. 현재 디자인 정리 단계에 새 기능 구현까지 한꺼번에 넣으면 범위가 다시 커진다.

[권장 실행 순서]
현재 안티그래비티 작업이 끝나고 저장 상태를 확인한 뒤 시작한다.
한 번에 한 파일의 프롬프트만 전체 복사해 붙여 넣는다.

01_백업과_지침정리.txt
  현재 상태 백업 → 디자인 지침 중복·충돌 정리. 앱 UI 코드는 아직 수정하지 않는다.
  완료 후 같은 프로젝트에서 새 채팅을 열고 02부터 진행하면 이전 지침의 영향을 줄이기 쉽다.
02_실행환경과_기준화면.txt
  현재 로컬 코드를 실행·검수할 수 있는 환경부터 확보한다.
03_공통디자인과_상세화면.txt
  하나의 디자인 기준을 정하고 실제 모임 상세 화면 하나에서 구현·검증한다.
04_홈화면.txt
  확정된 기준으로 실제 홈의 정보 순서와 모임 카드를 정리한다.
05_프로필과_커뮤니티.txt
  같은 기준을 프로필·커뮤니티에 순서대로 적용한다.
06_전체_디테일검수.txt
  실제 연결된 나머지 화면을 확인하고 회귀·작은 화면·큰 글자 상태를 검수한다.

각 단계의 결과가 '실행 미검증'이면 완료로 받아들이지 말고 먼저 검증 환경을 해결한다.
취향 판단은 03의 실제 상세 화면에서 한 번 하고, 이후에는 같은 방향을 유지한다.
문서·프롬프트를 계속 추가하는 대신 docs/OOMU_UI_GUIDE.md와 docs/UI_PROGRESS.md에 결정과 결과를 모은다.

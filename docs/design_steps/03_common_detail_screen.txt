OOMU의 docs/OOMU_UI_GUIDE.md와 docs/UI_PROGRESS.md를 읽고 3단계만 진행해줘. 보안 전용 파일은 읽거나 수정하지 마. 1단계 백업과 2단계의 로컬 실행 환경이 확인되어야 코드 수정을 시작해줘.

목표: 2030 여성이 편안하게 모임을 판단할 수 있는 차분하고 선명한 화면. 이번에는 공통 디자인 기준과 실제 연결된 모임 상세 화면 하나만 완성해줘. 새로운 안전귀가·매칭·승인 기능은 구현하지 마.

아래는 이번 OOMU 작업의 제안 기준이다. 공식 표준이라고 부르지 말고 실제 렌더링으로 조정해줘. 여러 스타일 후보를 계속 만들지 말고 이 방향 하나로 구현해줘.
- 주요 행동: 기존 브랜드 #F25767 한 색. 중립 배경 #FAFAFA, 카드 #FFFFFF, 기본 글자 #202124, 보조 글자 #667085, 경계선 #E7E9ED.
- 상태 색상은 실제 상태를 구분할 때만 사용하고 장식용 칩마다 다른 색을 배정하지 않는다.
- Pretendard를 사용할 경우 공식 배포 파일과 라이선스를 확인해 로컬 에셋으로 등록한다. 이미 허용된 폰트가 있으면 재사용한다. 폰트 이름만 문서에 쓰고 등록을 생략하지 않는다.
- 제목 22/20, 카드 제목 16, 본문 15, 보조정보 13을 기본 역할로 검토한다. 12 이하는 중요하지 않은 짧은 보조 표시에만 제한한다. 대부분은 굵기 400~600, 핵심 제목·행동만 700 정도를 사용한다.
- 본문 자간은 기본값부터 시작하고, 제목·본문·보조정보의 행간을 구분한다. 글자 크기를 줄이거나 전역 글자 확대를 막아서 겹침을 숨기지 않는다.
- 여백은 4·8·12·16·20·24·32 기준으로 정리하고, 관련 정보 사이는 좁게·서로 다른 구간 사이는 넓게 둔다. 광학적 보정은 허용한다.
- 아이콘은 동일한 계열과 시각적 무게로 맞춘다. 보조 아이콘 16~18, 주요 탐색 20~24 정도부터 검토하되 눌리는 영역은 최소 48×48 logical pixel을 유지한다.
- 버튼 12, 카드 16, 시트 24 정도의 모서리를 기본으로 검토하고 모든 구간에 보더·그림자·카드를 중첩하지 않는다.

구현 순서:
1. 위 기준을 공통 ThemeData/TextTheme와 최소한의 재사용 위젯에 연결하고 가이드에 실제 채택 값을 기록해줘. 토큰 파일만 만들고 기존 하드코딩을 그대로 두지 마.
2. main.dart의 실제 참조 경로를 재확인해 soso_car_detail_screen.dart의 현재 모임 상세에 먼저 적용해줘. 연결되지 않은 party_detail_screen.dart를 대신 수정하지 마.
3. 커버·제목·일정·장소·인원·호스트·소개·참여 행동의 읽는 순서를 정리해줘. 사진이 핵심 정보를 지나치게 밀어내지 않도록 커버 높이를 조정해줘.
4. 호스트 인증 문구와 온도 막대 겹침을 해결해줘. 인증 상태·수치는 기존 데이터의 확인 가능한 값만 표시하고 판정 로직은 변경하지 마.
5. 카카오맵·길찾기는 보조 행동으로 정리해줘. 아이콘을 무조건 줄이기보다 노란 면적·패딩·버튼 위치·글자 무게를 함께 조정하고 터치 영역은 유지해줘. 실제 로고와 로그인 버튼의 공식 규격은 임의 변경하지 마.
6. 주소·시간은 읽을 수 있게 줄바꿈하고, 제목·소개를 무조건 한 줄로 자르지 마. 데이터·좌표·신청 시뮬레이션 문제는 UI 작업과 섞어 고치지 말고 별도 이슈로 남겨줘.
7. 360/390/430 폭과 큰 글자 상태에서 실제 현재 코드의 화면을 확인하고 전후 스크린샷을 저장해줘. 관련 검사도 실행해줘. 공통 테마 변경의 영향을 받는 홈·프로필·커뮤니티도 기존 화면이 깨지지 않았는지 확인하되, 그 화면의 리디자인은 다음 단계로 남겨줘.

주요 수정 범위는 공통 테마·필요한 공통 위젯·실제 상세 화면·폰트 등록과 관련 테스트로 제한해줘. 기능·DB·인증·보안·git·배포는 변경하지 마. 변경 파일·검증 증거·미검증 항목을 기록하고 홈이나 다른 화면으로 확장하지 말고 여기서 끝내줘.

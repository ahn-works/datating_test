OOMU의 docs/OOMU_UI_GUIDE.md와 docs/UI_PROGRESS.md를 읽고 6단계만 진행해줘. 보안 전용 파일은 읽거나 수정하지 마.

이번 목표는 확정된 디자인 기준의 잔여 불일치를 찾고 고치는 것이다. 새 디자인 방향이나 새 기능을 만들지 마.

1. main.dart에서 실제 연결되는 화면을 기준으로 홈·상세·지도·프로필·설정·커뮤니티·채팅의 도달 가능한 경로를 확인해줘. 미사용 파일을 고친 것을 현재 앱 개선으로 집계하지 마.
2. 각 화면의 기본 글자·행간·색상 역할·외곽 여백·아이콘 계열·버튼·입력창·카드·시트가 공통 기준을 따르는지 확인해줘. 필요한 최소 수정만 해줘.
3. 360/390/430 폭, 글자 확대 1.0/1.3/2.0에서 긴 제목·주소·닉네임·소개·빈 이미지·키보드·하단 고정 버튼을 확인해줘. 말줄임·글자 축소·확대 제한으로 문제를 숨기지 마.
4. 정상·로딩·빈 상태·오류는 실제 도달 가능한 기존 테스트 수단으로 확인해줘. UI를 예쁘게 보이게 하려고 새로운 가짜 수치·승인·인증·성공 메시지를 넣지 마.
5. 데이터 상태·지도 좌표·신청 연동 같은 기능 문제는 별도 목록에 보존해줘. 이번 단계에 DB·인증·보안·신규 기능·유료 서비스 작업을 포함하지 마.
6. 최종 flutter analyze, 기존 전체 테스트, 필요한 위젯·회귀 검증을 실행해줘. 기존 실패와 신규 실패를 구분하고 테스트 삭제·검사 완화로 통과시키지 마.
7. 웹 검증과 안드로이드 검증을 구분해줘. 안드로이드 환경이 있으면 debug 실행으로 대표 화면을 확인하고, 없으면 안드로이드 확인은 미검증으로 남겨줘. Release 빌드·배포·git 작업은 하지 마.
8. 바뀐 현재 로컬 코드의 URL·실행 버전과 스크린샷을 연결해줘. 예전 공개 웹 화면이나 괄호 검사 결과를 변경 후 화면 검증이라고 보고하지 마.

같은 오류의 수정·재확인은 최대 3회로 제한하고 해결되지 않으면 재현 조건을 기록해줘. 이미 확인한 정상 화면을 이유 없이 재디자인하지 마.
최종 보고는 A4 한 장 이내로 실제 변경·화면 증거·검사 결과·미검증·남은 기능 이슈만 정리해줘. docs/UI_PROGRESS.md에도 이어서 할 위치를 남겨줘.

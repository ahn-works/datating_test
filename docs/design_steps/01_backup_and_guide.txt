현재 OOMU Flutter 앱의 이전 작업을 마무리하고 저장 상태를 확인한 뒤, 이번에는 백업과 UI 지침 정리만 해줘. 앱 코드는 아직 수정하지 마.

목표는 '2030 여성이 안전하고 자유롭게 모임을 열고 참여하는, 차분하고 읽기 쉬운 생활 커뮤니티'다. 새 매칭·안심귀가 기능 구현은 이번 단계에서 제외한다.

1. 현재 프로젝트가 C:\Users\DT4\Downloads\oomu_app인지 확인하고 동시에 소스를 수정하는 다른 작업과 겹치지 않게 해줘.
2. 프로젝트 외부의 oomu_app_backups 폴더에 현재 상태의 새 ZIP을 만들어줘. 기존 최초 백업은 덮어쓰지 말고, 원본 소스·에셋·설정·미저장 여부·제외 캐시를 구분해 기록해줘. ZIP 전체 읽기 검사와 임시 복원 후 포함 파일 해시 대조가 통과해야 다음 작업을 시작해줘. 백업을 외부에 업로드하지 마.
3. 보안 전용 파일은 열거나 수정하지 마. 혼합 문서는 디자인 관련 구간만 다루고 다른 정책·기능 정의는 보존해줘. 경계를 확실히 구분하지 못하면 그 문서는 변경하지 말고 이유만 남겨줘.
4. AGENTS.md, AI_INSTRUCTIONS.md, .agents/rules/oomu_integrated_rules.md, .antigravity/rules/ui_ux_design_rules.md, .antigravity/rules/prompt_routing_rules.md, .agents/skills/frontend-design/SKILL.md의 UI 지침 중복과 충돌을 정리해줘.
5. 디자인의 단일 기준은 docs/OOMU_UI_GUIDE.md로 모아줘. 다른 문서의 UI 구간은 짧은 요약과 이 문서의 참조로 정리하되, 원문 백업과 변경 내역을 보존해줘. 문서를 통째로 삭제·덮어쓰지 마.
6. '100점·무결점·12년 차' 수식어, UI 작업마다 모든 외부 서비스 벤치마킹·여러 모델 호출을 강제하는 규칙을 실제 확인 가능한 기준으로 바꿔줘. 앱의 AI 기능 코드나 모델 설정은 건드리지 마.
7. 무조건 대칭 2열·모든 문구 한 줄 말줄임·고정된 대형 커버 같은 규칙을 콘텐츠에 맞는 기준으로 정리해줘. Flutter 기본 API에 없는 wordBreak 전역 적용 지시는 제거하고 실제 API와 설치 버전으로 확인하도록 써줘.
8. main.dart에서 실제 화면 경로를 추적해 문서에 기록하고, 존재하지 않는 lib/features/... 경로와 현재 연결되지 않은 과거 화면을 구분해줘. 파일을 삭제하지 마.
9. IDE의 Customizations > Rules에서 활성 UI 규칙을 확인해줘. 현재 버전의 공식 규격에 맞춰 필요한 짧은 UI 규칙 하나가 상세 가이드를 참조하도록 해줘. 다른 정책 규칙의 활성 상태는 바꾸지 마. 전체 디자인 문서를 always_on으로 중복 삽입하지 마.
10. UI 완료 기준에서 자동 git push·배포를 분리해줘. 검증은 정적 분석·관련 테스트·현재 코드의 실제 화면 확인으로 구분하고, 못 한 것은 미검증으로 남기도록 해줘.

백업 경로·실제 수정한 문서·정리한 충돌·남은 항목만 짧게 보고하고 여기서 끝내줘. docs/UI_PROGRESS.md에 1단계 결과와 다음 시작점을 기록해줘. DB·인증·환경변수·git·배포는 변경하지 마.
